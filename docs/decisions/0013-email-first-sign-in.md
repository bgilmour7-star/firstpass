# Decision: Email-first sign-in, passwords and named coaches
Status: Accepted · 2026-10-19 (Brett: "These flows look good. Build." on the canvas "Firstpass Sign-in & Join")

## Context
Sign-in was a magic link only, on one screen that never said whether you were signing in or creating an account. A coach opening a join link saw "Sign in to Firstpass" with no team in view, waited for an email, then had to tap Join. We never asked for a name, so coaches showed up as email addresses. Links opened inside a mail app's own browser signed people in there, not where they started. Emails were Supabase's unbranded defaults.

## Options
| Option | Time to launch | Monthly cost | Lock-in | Future-proofing | Key risk |
|---|---|---|---|---|---|
| A. Email first, then the screen reacts: create (name + password), password, or link. Every email carries a 6-digit code and a link | A day | $0 | Supabase Auth (already) | Room for Google sign-in later | The email step says whether an address has an account |
| B. Keep link-only, add branding and a code | Hours | $0 | Same | None | Every new device still waits for an email |
| C. Separate Sign in / Create account pages | A day | $0 | Same | Same as A | People pick the wrong one and hit "already exists" |

## Decision
A.
- **Email first.** `sign_in_status(address)` says `new`, `password` or `link` (and the first name, for "Welcome back, Brett"). It reveals whether an address has an account, accepted for the pilot as Slack and Notion do.
- **New:** first name + password (8+). "Email me a sign-in link instead" is second. Either way Supabase emails a code to confirm the address; skipping that would let anyone sign up as someone else's email and join a team with it.
- **Has a password:** password, with "Forgot it?" and "Email me a sign-in link". **Link only** (everyone before today): "Email me a sign-in link", plus "Email me a link to set a password".
- **After a link sign-in, a password is offered once** (`/account/password?offer=1`), with "Not now". Account menu → Password changes it later.
- **`has_password` and `first_name` live in auth user metadata.** Supabase gives every account a hidden password, even link-only ones, so the metadata flag is the only reliable signal. `pw_prompted` records that the offer was answered.
- **Every Supabase email carries a 6-digit code and a button** to `/auth/confirm`, built from our `emailRedirectTo` (`?next=…&join=…`) plus the token hash, so it works in any browser. Templates are generated by `npm run email:templates` from the same frame as the app's emails.
- **Join links sign you in on the spot.** `/join/<code>` is public: inviter, team name and next practice (`join_link_preview`), then the email-first flow. Signing in through it joins the team in the same step and lands on "You're on <team>". The head coach gets "Kara joined U7 Clippers" with a way to remove them (the safety net for a forwarded link).
- **Invite by email** sends the team's join link with the address filled in. There is no per-person invite yet: the link stays the permission (decision 0011), and it works until the head coach turns it off.
- **Buttons never carry a team name** ("Join the team", "Confirm and join"); headings do, and they wrap.
- **`border-200` token** for inputs and outline buttons (3:1 in both themes); `border-100` stays a hairline.
